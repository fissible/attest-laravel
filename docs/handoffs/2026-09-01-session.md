## What shipped this session

Resolves [#9](https://github.com/fissible/attest-laravel/issues/9), the blocking handoff from
verdict-console ADR 0002 §8. Spec: `docs/specs/2026-09-01-verification-seam.md`.

- **New `@api` namespace `Verification\`** — `ChainVerifier` (container singleton, one method
  `verify(VerificationRequest): ChainVerificationResult`), `VerificationRequest` (readonly value
  object, validates range / blank chain / unranked min-anchor in its constructor),
  `ChainVerificationResult` (outcome, chainId, fromSeq, toSeqRequested, verifiedThroughSeq,
  brokenAtSeq, anchorOutcome, message, plus the core `VerificationResult` for detail).
- **Configuration parity with `attest:verify`** — default chain, trusted keys / key files
  (merged after config), min anchor, require-trusted-key, allow-provider-disagreement, and
  header-provider URLs all fall back to `attest.*` config, read at call time.
- **New supported HTTP seam** — header providers (Bitcoin Core RPC, Esplora) use a
  container-bound `Psr\Http\Client\ClientInterface` and PSR-17 factories when bound; otherwise
  Guzzle as before. Documented in `STABILITY.md` (configuration contract) and README. This is
  what lets the seam's tests exercise header resolution with a fake network instead of an
  `@internal` class.
- `STABILITY.md` and README updated. `Services\VerifyChain` stays `@internal` and is reused.

## Semantics worth remembering

- `verifiedThroughSeq` = `fromSeq + envelopeCount - 1` (null when 0), i.e. the last sequence
  whose structure **and** signature verified. It is set even when the policy verdict fails
  (`anchor_below_min`, `provider_disagreement`); `outcome` is the verdict.
- `anchorOutcome` is null both when no minimum applied **and** when a minimum applied but core
  produced no anchor verification (no matching anchor → `anchor_below_min` with a message).
- `brokenAtSeq` is carried verbatim from core: only `invalid_chain` / `invalid_signature`.
